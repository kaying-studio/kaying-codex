## これは何？

KayingCodex は、ゲームクリエイター向けのデスクトップアプリです。強力な AI エージェントと「品質保証フレームワーク」を組み合わせています。「横スクロールジャンプゲームを作って」と頼むと、いくつかのファイルを変更して「完了」と報告するだけでなく、**デザイン → シーン → ゲームプレイ → 統合 → テスト**という完全なワークフローに沿って、一歩一歩本当に動くものを作り上げます。

一般的な AI コーディングツールはプロジェクトをテキストのリポジトリとして扱いますが、ゲームは**シーン、アセット、バインディング、ゲームプレイロジック**が絡み合ったグラフです。KayingCodex の核心的な違いは次のとおりです：

- **コンパイルが通る ≠ プレイできる**：アセットが実際にバインドされているか、プレイヤーが実際に画面を見られるかを検証します。型チェックを通すだけではありません。
- **宣言した ≠ 有効になっている**：テクスチャを参照しても、それが実際にゲームにパブリッシュされたとは限りません。フレームワークは「証拠」がないと認めません。
- **長時間タスクでも主线を見失わない**：ひとつのゲームは複数フェーズにまたがります。KayingCodex は永続化されたタスク進捗で各ステップを保存するため、アプリを閉じて再度開いても中断した箇所から再開できます。
- **自己申告の成功では通さない**：AI が「できた」と言うだけでは不十分です。ディスク上に検証可能な証拠が実在して初めて、品質ゲートが開きます。

ひとことで言えば：**判断力は AI に、記憶・制約・検収はワークベンチに。**

## 主な機能

### 1. 完全なゲーム開発ワークフロー

KayingCodex は一度のゲーム開発を明確なフェーズに分割し、自動的に推進・記録・検収します：

```
要件 → 発見 → 能力監査 → 計画 → 契約凍結
     → シーン計画 → シーン構築 → シーンゲート
     → ゲームプレイ計画 → ゲームプレイ構築 → 統合ゲート
     → テスト → 意思決定 → リリース → 完了
```

各フェーズには明確な成果物と検収基準があります。現在の進捗をいつでも確認でき、「今どこまで進んでいて、次に何をすべきか」がわかります。

### 2. アセットを確実に反映

ゲーム開発で最もつまずきやすいのが「アートがバインドされていない」問題です。KayingCodex は**セマンティック・アセット層**を内蔵し、アセットをレビュー可能・パブリッシュ可能なパッケージとして管理します：発見、インポート、注釈付けから、シーンへのバインド、検証、パブリッシュまで、すべてのステップが記録されます。どのアセットが実際にゲームにバインドされ、どれが「宣言されただけ」なのかを明確に教えてくれます。

### 3. 役割分担による協働

ワークベンチ内部では、4 つの専門「ロール」がリレー形式で作業を担当します：

| ロール | 担当 |
|---|---|
| **ゲームディレクター** | 要件と検収基準、全体計画、重要な意思決定 |
| **シーンビルダー** | シーン、インターフェース、UI、アセットバインド |
| **ゲームプレイエンジニア** | ゲームプレイロジック、モジュール、ステートマシン |
| **品質テスター** | 検収スコアリング、問題のディレクターへのフィードバック |

作業はバトンのようにロール間で受け渡され、引き継ぎが明確です。「作業中に誰が何に責任を持つのか分からなくなる」ことはありません。

### 4. 内蔵ナレッジベース（オフライン対応）

AI にエンジンの API の使い方を推測させる必要はありません。KayingCodex にはバージョン管理された検証済み API ナレッジベース（26 分野・166 オペレーションをカバー）が内蔵されており、完全にオフラインで利用できます。生成されるコードが確実で正しい使い方に従うことを保証します。

### 5. 2 つの実行方式

| | **LocalRuntime（ローカル実行）** | **TapTap Runtime（公式ランタイム）** |
|---|---|---|
| 概要 | アプリ内蔵のクロスプラットフォーム Lua UI ランナー | TapTap 公式ローカルランナー |
| プラットフォーム | クロスプラットフォーム（macOS / Windows / Linux） | Windows のみ |
| 用途 | インタラクティブなデザインプレビュー、ローカル即時プレビュー | TapTap プラットフォームのビルド・リリース連携 |

LocalRuntime により、ネット接続や外部ツールに依存せず、アプリ内でシーンの実際のレンダリング結果を直接確認できます。

## 何ができる？

- **ゼロからゲームを作る**：アイデアを記述すると、ワークベンチが計画し、遊べるゲームプロトタイプを段階的に実装します。
- **ビジュアルデザインキャンバス**：デザインタブでシーンと UI を直接プレビュー・調整。WYSIWYG です。
- **アセットライブラリの管理**：アートやオーディオアセットのインポート、注釈付け、バインドを行い、確実にゲームに入るようにします。
- **TapTap へのリリース**：内蔵フローでリリース準備状態を検証し、ビルドを提出します。

## クイックスタート

### インストール

リリースページからお使いのプラットフォーム（macOS / Windows / Linux）用のインストーラーをダウンロードし、インストールして起動してください。アプリはデフォルトでゲーム開発モードで起動します。

### 初めての使い方

1. KayingCodex を起動し、ゲーム開発ワークスペースに入ります。
2. 新規プロジェクトを作成するか、既存のプロジェクトを開きます。
3. 作りたいゲームを自然言語で記述します（例：「2D 横スクロールジャンプゲーム。主人公は四角いブロックで、ジャンプとコイン取得ができるように」）。
4. ワークベンチはワークフローに沿って進みます：まず要件を確認し、シーンとゲームプレイを計画し、段階的に構築して検収します。
5. デザインキャンバスでリアルタイムに結果をプレビューし、問題なければリリースします。

### よく使う入り口

- **デザインタブ**：ローカルランタイムのシーンと UI をインタラクティブにプレビュー。
- **アセットライブラリ**：プロジェクトアセットの閲覧、インポート、バインド。
- **リリースパネル**：リリース準備状態の検証と TapTap への提出。
- **サイドバーの「実行」タブ**（Windows）：TapTap Runtime での実行。

## システム要件

- **LocalRuntime（ローカルプレビュー）**：macOS / Windows / Linux 対応。

## よくある質問

**Q：普通の AI プログラミングアシスタントと何が違うのですか？**
通常のアシスタントはファイルを修正すると「成功」と宣言しますが、ゲームが実際に動くか、アートがバインドされているかは検証しません。KayingCodex は永続化されたタスクフローと証拠駆動の品質ゲートにより、すべてのステップが確実に実行されることを保証します。

**Q：プロジェクトファイルはどこに保存されますか？**
ゲームプロジェクト内部のタスク進捗と証拠は、プロジェクトディレクトリ下の `.project/` に保存され、プロジェクトとともに移動するため、共同作業やバックアップが容易です。アプリ自体の設定とログはユーザーディレクトリの `~/.KayingCodex/` に保存されます。

**Q：ネット接続は必要ですか？**
ナレッジベースとローカルプレビューは完全にオフラインで利用可能です。TapTap プラットフォームとのビルド・リリース連携時にはネット接続が必要です。

**Q：対応プラットフォームは？**
ローカル開発とプレビューはクロスプラットフォーム対応です。TapTap 公式の実行とリリースは現在 Windows のみ対応しています。
